# Project Docs

Use this domain for game-specific and project-specific documentation that should not live inside the shared standards domain.

## Good Fits

- feature specs
- system overviews
- production notes
- milestone plans
- gameplay rules
- content pipelines unique to the project
- team runbooks tied to the current game

## Suggested Starting Structure

Create sections for the areas your team actually uses. Good starting categories are:

- Design
- Gameplay
- World
- UI
- Audio
- Production
- Release

Keep this domain lean at first. Add structure only when the project needs it.
